# 관리자 접근·초대 변경 기록

## 범위와 권한

사용자가 승인한 관리자 삭제, 민호 최고 관리자 보호, 최고 관리자 단일 양도, 초대 후 첫 비밀번호 생성 강제, 한글 초대메일 연결·지정 수신자 한 번 재발송을 구현했다. 유료 플랜·새 서비스 계정·도메인·DNS는 변경하지 않았다. 다른 조합 ERP 기능은 이번 구현 대상이 아니다.

## 현재 동작

- `minho@hoods.kr`는 기존 운영 조직의 유일한 최고 관리자다. 기존 정상 계정에는 첫 비밀번호 재생성을 요구하지 않는다.
- 최고 관리자의 역할 변경·중지·삭제는 서버 트리거로 거부한다. 공개 테이블에 사용자가 바꿀 수 있는 최고 관리자 플래그를 두지 않는다.
- 현재 최고 관리자만 같은 조직의 사용 중인 다른 관리자에게 권한을 양도할 수 있다. 현재 최고 관리자·대상 수정 시각을 재검사하고 조직/대상 행을 잠가 한 트랜잭션으로 단일 권한을 바꾼다. 이전 최고 관리자는 일반 관리자로 남아 이후 삭제할 수 있다.
- 관리자 삭제는 다른 일반 관리자의 작업공간 접근권한 해제다. 본인과 최고 관리자 삭제는 거부한다. 기존 Auth 계정, 발전소·점검·보고서와 작성 이력은 삭제하지 않는다. 삭제된 계정의 기존 토큰도 조직 자료를 읽거나 의뢰인 등록으로 우회할 수 없다.
- 최초 비밀번호 설정 여부는 서버 전용 `private.invited_password_setups`에 기록한다. 사용자 수정 가능한 메타데이터·브라우저 상태를 권한 근거로 사용하지 않는다.
- Supabase Auth는 초대 생성/확인 중 내부 무작위 암호를 만들거나 바꿀 수 있다. 단순 해시 존재/변경으로 완료 처리하지 않고, 이미 이메일 인증된 계정에서 이후 비밀번호가 실제 변경돼야 완료한다. 그 전에는 invited 상태를 유지하고 모든 기존 `private.has_org_role` 기반 업무 접근을 거부한다.
- 프런트엔드는 작업공간 조회 전에 서버 상태를 확인하며, 설정 전에는 비밀번호 생성과 로그아웃만 표시한다. 서버 상태 조회 실패도 차단한다. 사용자가 비밀번호를 저장한 뒤 계속하기로 재검사한다.
- 초대 대기 상태를 관리자가 화면에서 임의로 사용 중으로 전환하는 선택은 막았다. 서버의 비밀번호 선행 검사도 별도로 유지한다.

## 변경 이력

다음 마이그레이션은 순서대로 적용됐다. 이미 적용한 파일을 덮어쓰거나 합치지 않는다.

1. `20261016065801_super_admin_transfer_and_invite_password_gate.sql`
2. `20261016071747_track_invited_password_creation_explicitly.sql`
3. `20261016072246_bind_initial_password_gate_to_invited_membership.sql`
4. `20261016072442_require_verified_session_before_password_completion.sql`

개발 중 실제 Auth 회귀에서 확인한 내부 암호 처리 차이는 후속 마이그레이션으로 보완했다. `private.organization_super_admins`와 암호 설정 기록은 RLS·명시 deny 정책과 직접 권한 회수로 보호하고, 공개 RPC는 제한된 private 함수의 invoker wrapper로 제공한다.

## 메일 설정 결과

메일 작업은 사용자가 지정한 맥북의 기존 `solar-asset-care` 대화에서 수행했다. `[모두의햇빛]메인(맥북)` 업무 대화에는 요청하지 않았다. 기존 Resend 로그인·검증 도메인을 사용했고, 사용자의 별도 승인 후 SolarScope 발송 전용 키를 생성했다. 비밀값은 이 저장소나 문서에 보관하지 않는다.

- 발신 표시: `SolarScope <no-reply@auth.coopco.kr>`
- 제목: `[SolarScope] 태양광 진단 플랫폼 이용 초대`
- 내용: 조합명 없이 승인된 한글 본문, 실제 Supabase `ConfirmationURL` 버튼
- 대상: `bcymca@naver.com`
- 발송: 2026-10-16 16:28 KST, 한 번
- 증빙: Supabase `Sent invite email` 성공과 Resend `Delivered` 상태를 맥북 작업에서 대조
- 의미: 수신 메일 서버까지 전달된 상태이며 실제 열람·초대 수락·암호 설정은 수신자가 진행한다.

`supabase/templates/invite.html`과 `config.toml`에는 재구성용 비밀값 없는 템플릿 설정만 남겼다. SMTP 비밀번호를 로컬 설정으로 덮어쓰지 않는다.

## 검증

- 격리 PostgreSQL 17 회귀 25개 통과. 실제 Auth 시험과 구분하는 합성 스키마 시험이며 트랜잭션은 rollback했다.
- `demo-site/scripts/verify-admin-access.mjs`: 실제 Supabase Auth 발급 토큰으로 30개 통과. 임의의 `example.invalid` 시험 계정·별도 비운영 조직을 사용하고 메일은 보내지 않았다. 최고 관리자 보호·단일 양도·이전 최고 관리자 삭제·기존 토큰 차단·타 조직/전문가/익명 차단·초대 확인만으로 활성화되지 않음·실제 비밀번호 저장 후 정상 접근을 확인했다.
- 시험 중 감사 이력 FK 때문에 시험 조직 삭제가 거부돼, 해당 합성 조직의 감사 기록만 먼저 정리하도록 시험 cleanup을 수정했다. 잔여 합성 조직/계정도 정확한 식별값을 대조해 정리했고 최종 재조회에서 모두 0건이었다. 실제 샘플 발전소/점검과 운영 사용자 기록은 보존했다.
- 프런트엔드 자동검사 65개 및 TypeScript 검사 통과. 생산 빌드 성공. 공개 설정 누락/legacy 키는 빌드 선행 검사에서 거부한다. 클라이언트 번들에서 대상 프로젝트 공개 설정 포함과 현대식 서버 secret 값 미포함을 검사했다.
- 배포된 민호 세션에서 최고 관리자 배지·역할/상태 변경 비활성·삭제 버튼 없음, 다른 활성 관리자에 대한 양도 확인창을 확인했다. 확인창은 취소했으며 운영 권한은 시험으로 바꾸지 않았다.
- 390px 모바일 로그인·관리자 목록과 최종 320px 관리자 화면은 가로 넘침 없이 표시됐다. 실제 휴대전화의 키보드/메일 앱 링크 전환은 별도 기기 시험이다.
- 보안 advisor 신규 RLS/권한 지적 없음. 기존 유출 암호 검사 미활성 경고는 이번 범위에서 유료 설정을 바꾸지 않았다. [공식 보완 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
