범위
- 이전 세 역할 재검수에서 확인한 일정 취소, 역할과 맞지 않는 빈 화면 안내,
  점검별 바로가기 부재를 보완한다. 기존 기능·권한과 최소 정보 사진 진단은 유지한다.
- DB/마이그레이션/RLS/패키지/SMTP/환경변수/공개 범위/실제 사용자 권한은 변경하지 않는다.

수정
1. 일정 수정 취소: local dirty·busy와 실제 lock을 공통 폐기 확인에 연결.
   깨끗한 취소는 바로 닫고 변경 시 확인, 이어서 작성은 같은 입력 보존.
   저장 완료 닫기는 기존 경로를 유지하며 pending/CAS/한국 시간/날짜 순서는 변경하지 않는다.
2. 빈 보고서/조치: 쓰기 가능 여부, 점검 유무, 다른 점검 자료 유무에 따라 안내한다.
   고객에게 생성/승인/등록 권한이 있다고 안내하지 않는다. 다른 점검 자료가 있으면
   기존 전체 보기 상태만 켜며 새 데이터 접근 권한이나 요청을 만들지 않는다.
3. 점검 바로가기: 현황과 점검 목록의 명시적 버튼. 현재 RLS로 조회한 점검 ID만
   대상이며 익명/알 수 없는 역할/목록 밖 ID는 거부한다. 고객은 자기 발행본이 있으면
   보고서, 아니면 의뢰 진행으로; 직원은 진행 건의 자료 작업/발행·종료 건의 보고서로 연다.
   메뉴+ID를 한 번에 이동하며 기존 이동 보호와 이력 저장을 사용한다. 확인창 이후에도
   현재 역할·목록으로 다시 해석한다. URL이나 버튼을 서버 접근권한으로 취급하지 않는다.
- React Compiler 검사의 forward-capture 문제는 이벤트 함수 선언을 기반 상태와
  memoized 조회 뒤에 배치해 해결했다. lint 억제나 조회 dependency 제거는 하지 않았다.
