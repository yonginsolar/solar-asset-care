2. 우선 보완 권고 — 재현된 문제

A1. P2 — 관리자 기본 점검 번호의 재방문 중복
재현:
  관리자 > 점검 > 기본 번호 INS-20261017로 가상 점검 접수 성공.
  운영 현황으로 이동한 뒤 점검 메뉴를 다시 열면 INS-20261017로 되돌아옴.
  다음 접수를 누르면 inspections_organization_id_inspection_code_key 중복 오류.
영향:
  같은 날 여러 점검을 정상 접수하는 과정에서 실패한다. 번호를 직접 바꾸면
  우회할 수 있지만 처음 쓰는 관리자는 원인을 알기 어렵다.
원인 근거:
  demo-site/components/live/live-app.tsx:2991 날짜만 사용한 초기 번호.
  같은 파일:3065 관리자 직접 INSERT, :3085 접수 직후 번호만 별도 생성.
권고:
  서버에서 충돌 없이 발급하는 번호 또는 안전한 기본 식별자를 사용하고,
  중복 제약은 유지한다. 수동 번호 중복에는 해결 가능한 한국어 안내를 제공한다.
오류는 접수 뒤 DOM의 alert에서 확인했다. admin-default-number-conflict.png는
당시 제출 버튼 쪽 스크롤 위치를 기록하며, 오류 안내는 화면 위쪽에 있어 보이지 않는다.

A2. P2 — 보고서 메일 링크의 로그인 후 목적지 유실

  별도 회차에서 같은 경로를 반복하여 다시 재현했다.
영향:
  메일을 받은 고객이 보고서를 다시 찾아야 한다. 인증·권한 차단은 정상이나

원인 근거:
  demo-site/components/live/live-report.tsx:82 로그인 링크에 보고서 목적지 없음.
  demo-site/components/live/live-app.tsx:1008 역할별 기본 포털 이동.
권고:

A3. P2 — 고객의 미발행 점검 '열기'가 사실상 목록 재선택에 그침

영향:
  고객은 버튼이 동작하지 않는다고 느낄 수 있다. 어떤 점검을 선택했는지,
  담당자 확인·자료 대기 등 다음 단계가 무엇인지 드러나지 않는다.

A4. P2 — 입력 실패 안내가 영어이며 모바일 화면 밖에 표시됨
재현:

영향:
  잘못된 고객 자료는 저장되지 않으므로 자료 무결성은 유지된다.
  다만 사용자는 무엇을 고쳐야 하는지 알기 어렵다. 모바일에서는 제출 버튼으로
  스크롤한 위치가 유지되어 위쪽의 오류 안내가 보이지 않았다. 저장 버튼을 눌렀는데
  반응이 없는 것으로 받아들일 수 있다. A1의 중복 접수 때도 같은 표시 문제가 있었다.
원인 근거:
  demo-site/components/live/live-customers.tsx:388 공백 이름의 사전 검증 없음.
  같은 파일:123 공급자 오류 문구가 화면에 전달됨.
권고:
  trim 기준 필수 검증·해당 입력란 포커스·한국어 안내를 추가하고,
  제출 실패의 오류 영역을 현재 화면에서 알아차릴 수 있게 한다.
  서버 제약과 권한 검사는 그대로 유지한다.
오류 문구는 DOM alert에서 확인했다. customer-whitespace-error.png에는
당시 고객 등록 버튼 주변이 보이며, 화면 위에 추가된 오류 안내는 보이지 않는다.

3. 기능 외적인 안내·복구 보완

B1. P2 — 의뢰 접수 뒤 사진 전달·다음 행동·문의 경로 안내 부족
  가상 의뢰를 실제로 접수하면 '점검을 접수했습니다.'와 요청 목록만 보인다.
  고객 화면에는 사진을 어디에 전달하는지, 담당자 확인을 기다리는지,
  문제가 있으면 누구에게 문의하는지 안내가 없다.
  공개 첫 화면에도 별도 도움말·문의 진입점이 없고, 약관 페이지는 운영정보 준비 중이다.
  운영주체·문의처 미확정은 기존 설정 대기사항이며 이번에 새로 생긴 코드 오류가 아니다.
  권고: 기존 직원 전용 업로드 권한을 유지하면서 실제 운영 방식에 맞는 안내를 제공하고,
  관리자 설정에 확정된 연락처가 있을 때만 표시한다. 임의 연락처나 처리기한을 만들지 않는다.

B2. P3 — 잘못된 주소에서 홈으로 돌아갈 길이 없음
  공개 사이트 /not-a-real-page에서 '404 / This page could not be found.'만 표시됨.
  한국어 설명, 홈·로그인 이동 링크가 없다. 로컬과 공개 사이트에서 모두 확인했다.
  권고: 기존 404 상태 코드를 유지하며 홈/작업공간 복귀 링크를 제공한다.
  증거: public-404-no-recovery.png
