## ✅ 이번에 실제 저장·사용하도록 연결한 기능

### 비밀번호 없는 게스트 둘러보기

로그인 화면에서 `/guest`로 들어가 의뢰인·전문가·관리자 화면 예시를 읽을 수 있다. 운영 계정을 만들거나 로그인 인증을 생략하는 기능이 아니다. 고정 합성 자료만 사용하고 운영 데이터·원본·고객 계정·이메일은 조회하지 않는다. 게스트 역할 선택은 예시 메뉴 구성에만 영향을 준다. 등록·수정·승인·파일 전송은 없으며 기존 업무 흐름의 권한은 바꾸지 않았다.

추가 검사 후 단위 시험은 51개다. `node scripts/verify-guest.mjs`는 로컬의 역할·메뉴 조합 27개와 비공개 API 거부 3개를 데이터 변경 없이 검사한다. 배포 후에는 `SOLAR_GUEST_ORIGIN=https://solar-asset-care-demo.kimminho0914.chatgpt.site`로 같은 검사를 수행한다. 다른 원격 주소는 거부한다.

### 계산·촬영 기준

관리자의 ‘계산·촬영 기준’에서 발전시간, 열화율, 보정계수, 단가, 성능비 구간, 일사량·풍속·각도·거리, 온도차 기준과 이상유형별 개선가능비율을 등록한다. 적용 시작일과 변경 사유를 남기며 기존 판본을 덮어쓰지 않는다. 확인되지 않은 단가·촬영 기준은 자동으로 활성화하지 않았다.

REC 단가는 원/kWh 단위다. 원/MWh 자료는 1,000으로 나누어 입력해야 한다. 기본으로 표시하는 일부 숫자는 요구서의 초기 참고값이며 검증된 운영 단가가 아니다.

### 촬영조건·발전량 평가

관리자·배정 전문가가 촬영조건, 측정 시각·출처, 분석기간·실발전량·출처와 예상 수리비를 입력한다. 설비용량·설치연도는 저장된 발전소에서 가져오고 서버가 계산한다. 화면에서 결과값을 조작해 보내도 저장 결과로 쓰지 않는다.

분석기간은 양 끝 날짜를 포함하고 실발전량과 기대발전량의 기간을 일치시킨다. 손실량은 0 이상으로 표시한다. 회수기간은 해당 기간의 회수가능액을 365일로 환산해 계산하며, 금액은 원 단위 반올림 표시·내부 계산값은 정밀도를 유지한다. 이 계산은 입력 기반 추정이며 일사 계측으로 산출한 IEC 성능비가 아니다.

일사량·풍속·각도·거리 경고가 있으면 보고서 검토 요청이 차단된다. 관리자만 사유를 기록해 예외 승인할 수 있다. 전문가는 예외 승인을 할 수 없으며 평가를 다시 수정하면 종전 예외 승인을 자동 승계하지 않는다. 다른 사람이 먼저 저장한 평가를 덮어쓰지 않도록 변경 차수를 확인한다.

### 전문가 수동 소견·수정

시스템 후보가 없더라도 수동 소견을 등록할 수 있다. 이상 유형, 심각도, 모듈 위치, 원본과 이미지 내 영역, 측정 온도·온도차, 측정 근거와 권고 조치를 기록한다. 기존 후보를 수정 채택하거나 제외할 수 있고 변경 전후와 담당자·시각을 보관한다. 제외는 기록 삭제가 아니다.

온도 수치를 입력하려면 별도 측정 근거가 필요하다. 색상 점수를 섭씨 온도로 바꾸지는 않는다. 내부 원본 미리보기를 유지하며 고객용 이미지는 아래의 별도 승인 절차를 거친다.

### 고객용 사진·가림 처리·이상 위치

관리자·배정 전문가는 ‘보고서 사진’에서 JPG·PNG 원본을 선택하고 개인정보 영역을 검게 가린 뒤 설명과 함께 저장한다. 가림 영역은 왼쪽·위쪽 위치와 너비·높이를 백분율로 지정하며 최대 20개다. 원본을 유지하고 긴 변 1280px 이하의 별도 JPG를 만들며 부가 메타데이터를 제거한다. 자동 얼굴·번호판 탐지는 아니다.

관리자는 실제 저장된 사진이 정상 표시된 뒤 포함 승인을 누른다. 전문가 혼자 승인할 수 없으며 점검당 최대 12장이다. 검토 요청 시 승인 사진과 확인값이 보고서 보관본에 고정된다. 이후 사진을 제외해도 기존 검토본은 변하지 않으므로 기존 보고서를 바꾸려면 수정 요청·재검토 또는 개정본을 사용한다. 사진을 고치려면 새 파생 사진을 저장한다.

고객 보고서와 PDF에는 승인 사진, 연결된 채택 소견의 영역·번호와 동일 분석기간의 현재 수익·개선 후 추정·기대 수익 비교가 표시된다. 사진이 없으면 임의 이미지를 넣지 않는다. 과거 텍스트 PDF는 그대로 다운로드하고 새 보고서만 새 서식으로 생성한다. 위치 지도와 TIFF 고객용 미리보기는 남아 있다.

### 복수 원본·중단 후 재개

‘열화상 업로드’에서 한 번에 최대 20개, 파일당 50MB까지 선택한다. 한 파일씩 전송하고 진행률·완료·실패를 각각 표시한다. 일시정지 또는 연결 실패 후 다시 시작할 수 있다. 창을 닫았을 때는 같은 계정·점검·파일 종류에서 같은 파일을 다시 선택해야 한다. 브라우저의 재개 정보는 보조 정보이고 원본·등록 여부는 서버에서 확인한다. 재개 주소가 만료되거나 브라우저 저장 정보가 없으면 처음부터 전송한다.

6MB 단위 전송을 사용하며 같은 내용은 같은 점검·종류에서 중복 등록하지 않는다. 전송 후 목록 등록만 실패해도 다시 선택하면 기존 바이트를 확인하고 등록을 복구한다. 신규 파일의 수정 시각을 실제 촬영 시각으로 잘못 기록하지 않는다. 촬영 시각은 촬영조건 평가에서 입력한다. 등록 원본의 교체·확인값 변경·일반 계정 삭제를 차단했다. 실패한 임시 파일과 만료된 전송의 자동 정리는 별도 남은 운영 작업이다.

### 검토 보관본과 PDF 발행

검토 요청 시점의 발전소·촬영조건·계산 기준·계산 결과·채택 소견·후속 조치·원본 목록을 하나의 보관본으로 고정한다. 이후 원자료를 수정해도 검토·승인·발행 보고서 내용은 바뀌지 않는다. 수정 요청이나 승인 취소 후 재검토하면 새 보관본을 만들고 이전 검토 내용은 감사기록에 남긴다.

관리자가 ‘최종 발행’을 누르면 서버가 승인된 보관본으로 PDF를 만들고 비공개로 보관한 뒤 발행한다. PDF 저장 실패 시 발행 상태로 넘어가지 않는다. 반복 요청은 기존 파일을 재사용하며 덮어쓰기를 허용하지 않는다. 의뢰인은 발행된 본인 보고서만 다운로드할 수 있고, 회수하면 같은 로그인 상태에서도 접근을 잃는다. 이미 내려받은 파일까지 원격 삭제하는 기능은 아니다.

PDF는 한글 글꼴, A4, 최소 11pt, 자동 페이지 나눔과 승인 사진·소견 영역·경제성 차트를 포함한다. 지도는 아직 포함하지 않는다.

### 고객 파일 전달·캐시 보호

비공개 저장소라도 이미 허용된 파일 주소가 CDN 캐시에서 계속 응답하는 현상을 실제 시험에서 확인했다. 캐시 시간을 0으로 낮추는 것만으로 충분하지 않았다. 의뢰인의 저장소 직접 접근을 막고 사이트 서버가 매 요청마다 현재 사용자와 보고서 보관본 접근 권한을 확인한 뒤 파일을 전달하도록 변경했다. 고객에게 서명된 저장소 주소를 발급하지 않는다.

권한 판단은 기존 사용자 세션과 조직·발전소 권한으로 하고 통과한 파일 바이트만 서버 전용 `SUPABASE_SECRET_KEYS`로 읽는다. 이 값은 Git 제외 로컬 환경 파일에만 설정했고 브라우저는 publishable key를 유지한다. 향후 호스트에도 서버 비밀 설정이 필요하다. 회수 후 앱 API와 저장소 직접 접근을 모두 시험했다. 이미 받은 사본의 원격 삭제와 내부 직원용 기존 원본의 서명 URL·권한 회수 캐시 검수는 별도다.

### 재활용 인증서 등록·공개·수정

관리자의 ‘재활용 인증서’에서 실제 발급받은 PDF·JPG·PNG(10MB 이하)를 발전소에 연결한다. 제목·발급기관·발급일은 필수, 인증서 번호·패널 수는 선택이다. 발급일은 한국 날짜 기준 미래·유효하지 않은 날짜를 거부한다. 초기 상태는 확인 대기이고 관리자만 조회한다. 내려받은 파일의 내용과 개인정보 범위를 확인한 뒤 관리자가 공개하면, 해당 발전소에 연결된 의뢰인과 배정 전문가가 제목 검색·발전소 필터·20건 단위 목록·다운로드를 사용할 수 있다.

관리자는 공개 회수 사유를 남길 수 있다. 회수하면 같은 계정의 새 조회·다운로드가 차단된다. 확인 대기·회수 상태에서 발전소와 표시 정보를 사유와 함께 수정할 수 있으며, 수정 후 다시 확인·공개해야 한다. 공개된 정보를 바로 덮어쓰거나 동시에 바뀐 예전 화면으로 수정하는 것은 차단한다. 파일 바이트·경로·확인값은 유지하며 변경 전후를 감사기록에 보관한다.

새 비공개 저장소는 관리자까지 직접 조회를 허용하지 않는다. 사이트 서버가 현재 인증서 접근 권한을 확인한 뒤 원본 확인값과 형식을 검사해 `attachment`, `no-store`, `nosniff`, `sandbox` 응답으로 내려준다. PDF는 100쪽 이하, 스크립트·자동 실행·삽입 첨부 등을 제한하며 원본을 재작성하지 않는다. PNG는 400만 화소, JPG는 2,000만 화소까지다. 검사는 악성코드 전체 검사·발급기관 진위·전자서명 유효성 보증이 아니다. 이미 내려받은 파일을 원격 삭제하지 않는다.

### 실제 등록 오류 수정

발전소를 저장한 직후 저장 결과를 읽는 과정에서 권한 확인이 새 행을 보지 못해 등록 전체가 취소됐다. 관리자·배정 전문가의 기존 접근 범위를 유지하면서 발전소·점검·수동 소견 저장 결과를 정상적으로 읽도록 수정했다.

### 업체 상세정보와 3개 견적 수용시험

관리자는 ‘업체·견적’에서 업체명·유형·지역·평점과 함께 사업자등록번호, 면허·등록번호, 담당자명·연락처·이메일과 관리 메모를 등록하고 수정한다. 공개 비교정보와 관리자 전용 상세정보는 표를 분리해 저장한다. 업체 저장은 한 번의 관리자 전용 처리로 완료하고 변경 이력을 남긴다. 같은 조직의 업체명·유형 또는 사업자등록번호가 겹치면 등록하지 않으며, 전문가·의뢰인·다른 조직 관리자는 상세정보를 읽거나 바꿀 수 없다.

합성 업체 3곳을 만들어 견적 요청 → 1·2건 회신 중 의뢰인 표시 → 3건 회신 후 선택 가능 → 의뢰인 1곳 선택 → 선택·미선택 상태와 수수료 계산까지 실제 세션으로 검사했다. 업체 표 직접 쓰기, 업체 2곳만 연결, 전문가 회신 입력, 미연결 의뢰인 선택과 타 조직 수정은 모두 거부됐다. 시험 계정·조직·업체·견적은 종료 시 삭제했다. 업체 전용 로그인이나 업체가 직접 제출하는 링크는 이번 MVP에서 활성화하지 않았다.

| 데이터베이스 업무·권한 시험 | 통과 | 두 조직, 관리자·배정/미배정 전문가·연결/미연결 의뢰인. 하나의 취소되는 시험 트랜잭션으로 실행 |
| 실제 Auth 세션·API·파일 시험 | 온라인 105개 통과 | 사용자 5명·조직 2개, 업체 상세정보·3개 견적·수수료·선택, 7MB 중단·1MB 재개, 승인 사진·PDF·인증서 등록/공개/정정/회수, 원본 유지, 연결 해제·직접 주소 차단. 실제 고객 3건 검수와 다름 |
| PDF A4·한글·최소 11pt | 통과 | 사진·마커·차트 포함 PDF 4쪽을 렌더링하고 글자 크기·경계·단위 문자를 확인 |
| 모바일 화면 검수 | Chrome 390px·320px 역할별 시험 + 업체 관리 헤드리스 재검수 | 신규 업체 등록·상세정보·업체 3곳 선택·견적 카드에서 가로 넘침, 화면 밖 입력, 이름 없는 조작 요소가 없음을 확인. 실제 휴대폰 기기·복수 파일 선택·모바일 재개는 미검증 |
| 보안 진단 | 경고 1건 남음 | 유출 비밀번호 차단 미활성. 유료 플랜·설정 변경하지 않음 |

실제 세션 시험은 원본 업로드와 체크섬 확인 → 전문가 수동 판정·서버 계산 → 검토 → 관리자 승인 → PDF 보관 → 발행 → 의뢰인 다운로드까지 진행했다. 타 조직·타 의뢰인·익명 접근 거부, 전문가 승인 거부, PDF 덮어쓰기 거부, 원자료 변경 후 내용 불변, 회수 후 접근 거부를 확인했다. 이 시험은 브라우저 클릭 시험이나 방사온도 분석 정확도 시험이 아니다.

위 API 시험과 별개로 Chrome 화면 조작 시험도 진행했다. 모바일에서 입력·등록한 합성 자료로 보고서 초안 → 검토 → 승인 → 발행을 완료했고, 다운로드된 PDF가 서버 보관본과 일치함을 확인했다. 브라우저 파일 선택은 자동화 확장프로그램의 파일 접근 권한 때문에 중단했으며, 그 이후 화면 시험에 필요한 원본만 합성 계정의 정상 API로 등록했다. 이를 브라우저 업로드 성공으로 간주하지 않는다.

모든 임시 계정·조직·업무 행·Storage 객체는 정리했다. 사용자 계정, 비밀번호와 기존 운영 조직은 변경하지 않았다. 로컬 시험 PDF만 재검증용으로 남겼으며 Git 대상에서 제외했다.

### 이번 추가 실사용 시험에서 확인한 점

기존 관리자 로그인을 유지하기 위해 같은 로컬 서버의 별도 루프백 주소에서 합성 계정으로 시험했다. 관리자 인증서 입력(파일 선택 제외)·검색 결과 없음·검색 결과 다운로드·회수·재공개·정보 정정, 전문가 가림 영역 오류 수정·저장, 관리자 사진 승인, 의뢰인 인증서 조회·다운로드·수정 후 재공개 전 비노출을 직접 확인했다. 실제 내려받은 인증서와 보고서 PDF의 확인값도 원본과 일치했다.

320px·390px 화면에서 인증서 입력과 보고서 읽기를 검사했다. 문서 전체 가로 넘침은 없었고 보고서 소견 표는 내부 가로 스크롤 방식이다. 가림 저장 시험은 작은 합성 원본을 사용했으므로 실사진의 가림 품질 검수를 대신하지 않는다. 보고서에서는 별도 합성 컬러 사진·검은 영역·소견 번호와 차트를 육안 확인했다. 의뢰인 목록의 중복 안내와 링크 안에 버튼이 중첩된 구조를 정리하고, ‘보고서 보기’ 링크의 새 탭 열기를 재시험했다.

화면에서 임시 계정을 로그아웃한 뒤 API 시험이 예전 세션으로 404를 기대해 실패하는 시험 도구 문제도 발견했다. 이후 화면 시험 종료 시 세션을 다시 얻도록 수정했다. 로그아웃한 토큰의 401 거부와 새 로그인 후 회수된 보고서의 404 거부를 추가 시험했고, 최신 독립 API 전체 실행은 88개 모두 통과했다. Chrome 콘솔에는 기존 RHWP 확장프로그램이 HTML 속성을 넣어 생기는 hydration 경고가 남아 있으며 이를 앱 오류가 없는 것으로 숨기지 않는다.

## 🧭 집에서 확인할 순서

1. 관리자 로그인 후 ‘내 계정’에서 임시 비밀번호를 변경한다.
2. ‘계산·촬영 기준’에서 실제 사용할 값과 적용 시작일·출처를 등록한다.
3. 발전소의 설비용량·가동 시작일을 확인하고 점검과 전문가를 배정한다.
4. 원본 업로드 → ‘촬영조건·발전량’ 저장 → ‘후보 판정’에서 채택·수정·제외한다.
5. ‘보고서 사진’에서 원본 선택 → 필요한 영역 가리기 → 설명 입력·저장 → 관리자가 저장된 사진을 확인·승인한다.
6. 보고서 초안 생성 → 검토 요청 → 사진·소견·금액 확인 → 승인 → 최종 발행한다.
7. 연결된 의뢰인 계정에서 보고서와 ‘보관 PDF 다운로드’를 확인한다.

## 개발 재검증

- `demo-site/`: `npm test`, `npx tsc --noEmit`, `npm run lint`, `npm run build`.
- DB: `supabase/tests/operational_workflow.sql`은 최종 `ROLLBACK`까지 전체 실행한다.
- 실제 세션: 로컬 서버 실행 후 `SOLAR_ACCEPTANCE_RUN=1 node scripts/verify-live-workflow.mjs`. 지정된 개발 프로젝트에 합성 자료만 생성·정리한다. 서버 비밀 키는 CLI·프로세스 메모리에서만 사용한다. 파일 전달용 서버 비밀값은 Git 제외 로컬 환경 파일에 둔다.
- 역할별 화면 시험: 위 명령에 `SOLAR_UI_ACCEPTANCE=1`을 추가하면 합성 계정의 로그인 정보만 출력하고 45분 이내 또는 Enter 입력까지 기다린다. 기존 사용자로는 시험하지 않는다. 끝나면 브라우저에서 임시 계정을 로그아웃한 뒤 Enter를 보내 정리하고, 성공·실패 어느 경우든 잔여 계정/객체를 확인한다. 인증 토큰·서버 키는 출력하지 않는다.
- 업체 관리 모바일 자동검사: 합성 화면 시험이 기다리는 동안 `SOLAR_UI_QA_RUN=1`, 합성 관리자 이메일·비밀번호를 프로세스 환경으로만 전달해 `node scripts/verify-mobile-ui.mjs`를 실행한다. 로컬 주소만 허용하며 320px·390px의 업체 등록·수정·3곳 선택 화면을 검사하고 계정 값을 파일에 남기지 않는다.
- PDF 글꼴은 저장소의 정적 파일을 사용한다. 현재 Sites에 `REPORT_ASSET_ORIGIN`과 서버 전용 `SUPABASE_SECRET_KEYS`를 설정했다. 최신 재검증은 코드 검사 56개·온라인 Auth/API/Storage·업체 견적 시험 105개를 통과했다. 위 9월 5일의 46개·88개와 최초 배포의 47개·90개는 당시 결과로 유지한다.
- 온라인 재검증은 추가로 `SOLAR_ACCEPTANCE_DEPLOYED=1` 및 `SOLAR_ACCEPTANCE_ORIGIN=https://solar-asset-care-demo.kimminho0914.chatgpt.site`를 명시해야 한다. 다른 원격 주소나 온라인에서의 대화형 시험 대기는 거부한다. 합성 계정만 사용하고 종료 시 정리한다.
- Supabase 스킬의 변경 이력·최소 권한·검증 원칙을 따라 새 표의 익명·직접 쓰기를 차단하고 업무 함수·역할 시험을 추가했다. PDF 스킬의 렌더 검증에서 CFF 글꼴 문제를 발견해 정적 TrueType으로 교체했다.
