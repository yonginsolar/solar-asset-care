# SolarScope 운영형 사이트 + 요구사항 데모

태양광 검사 접수부터 열화상 원본, 전문가 판정, 보고서 승인과 유지보수까지 Supabase에 저장하는 운영형 1차 사이트다.

「솔라이음 AI진단 플랫폼 개발」 PDF의 관리자 A-1~~A-6, 고객 C-1~~C-5 샘플 흐름은 `/demo`에서 시연한다. 실제 구현·검증·미구현 범위는 [2026-09-05 개발 현황](../docs/DEVELOPMENT_STATUS_2026-09-05.md)이 최신 기준이며, 요구서 전체 검수 완료를 뜻하지 않는다.

## 실행

```bash
npm install
cp .env.example .env.local
npm run dev
```

기본 주소는 `http://localhost:3000`이다.

## 명령

```bash
npm run lint
npm test
npm run build
```

## 경로

- `/`, `/admin`: 로그인과 실제 Supabase 데이터를 사용하는 운영 화면
- `/demo`: PDF의 관리자 A-1~~A-6, 고객 C-1~~C-5를 모두 살펴보는 샘플 화면
- `/reports/:id`: 로그인 권한으로 실제 보고서를 읽는 A4 인쇄 화면
- `/api/reports/:id/pdf`: 사용자 세션으로 PDF 보관·다운로드. POST는 관리자·승인 보고서만 생성하고, GET은 보고서 열람 권한을 재확인한다.

## 실제 평가·발행

1. 관리자가 ‘계산·촬영 기준’에 적용일·사유와 기준값을 등록한다. 확인되지 않은 단가·촬영 기준은 자동 활성화하지 않는다.
2. 발전소 용량·가동 시작일을 저장하고 점검을 생성·전문가 배정한다.
3. 원본 업로드, ‘촬영조건·발전량’ 입력, ‘후보 판정’에서 수동 소견·채택·수정·제외를 처리한다.
4. 보고서 검토 요청 시 내용을 고정하고 승인 → PDF 생성·보관 → 발행한다. 보관 실패 시 발행하지 않는다.
5. 연결된 의뢰인이 보관 PDF를 다운로드한다. 원자료를 수정해도 과거 PDF와 검토 내용은 바뀌지 않는다.

PDF는 정적 TrueType 한글 글꼴을 저장소에 포함한다. `REPORT_ASSET_ORIGIN`은 서버가 글꼴을 가져올 신뢰된 주소이며 향후 호스트에서 명시적으로 설정한다. 사용자 요청의 Host 헤더로 만들지 않는다. `NEXT_PUBLIC_*`가 아닌 서버 설정이며 비밀키는 필요 없다.

명시적으로 합성 자료 기반 실제 세션 시험을 실행하려면 로컬 서버를 켠 상태에서 `SOLAR_ACCEPTANCE_RUN=1 node scripts/verify-live-workflow.mjs`를 실행한다. 이 스크립트는 개발 프로젝트에 임시 계정·조직·파일을 생성한 뒤 정리한다. 기존 사용자 비밀번호는 변경하지 않는다.

관리자 업체 화면의 반응형 자동 검수는 위 시험을 `SOLAR_UI_ACCEPTANCE=1`로 일시정지한 동안 합성 관리자 계정만 환경값으로 전달해 `SOLAR_UI_QA_RUN=1 node scripts/verify-mobile-ui.mjs`를 실행한다. 이 도구는 로컬 주소만 허용하고 계정 값을 파일이나 결과에 남기지 않으며 320px·390px 화면의 가로 넘침, 화면 밖 입력 요소와 이름 없는 조작 요소를 검사한다.

## 데이터와 보안

- Supabase 브라우저 연결에는 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`만 사용한다.
- secret key와 legacy `service_role` 키는 브라우저나 저장소에 두지 않는다.
- 역할은 관리자·전문가·의뢰인 3개다. 의뢰인은 직접 가입하고, 전문가·추가 관리자는 관리자 초대 메일로 가입한다.
- 로그인 후 모든 역할의 ‘내 계정’ 메뉴에서 비밀번호를 변경할 수 있다. 비밀번호를 잊었다면 로그인 화면에서 변경 메일을 요청한다.
- 가입 확인·비밀번호 변경 메일은 `NEXT_PUBLIC_AUTH_REDIRECT_URL`로 돌아온다. 이 주소는 Supabase Auth의 Redirect URLs 허용 목록에도 등록해야 하며, 환경값을 생략하면 사용자가 연 현재 사이트 주소를 사용한다.
- 의뢰인은 연결된 본인 발전소와 발행 보고서만, 전문가는 배정된 점검만, 관리자는 전체 업무 데이터를 조회한다.
- 업체는 내부 사용자 역할과 분리한다. 관리자는 업체 기본정보와 관리자 전용 사업자번호·면허·담당자 정보를 함께 등록·수정하고, 의뢰인은 본인 발전소에 제출된 공개 견적만 비교·선택한다. 같은 조직의 업체명·유형 및 사업자번호 중복을 막고 변경 이력을 남긴다.
- 관리자는 발전소·의뢰인·업체 3곳을 묶어 견적 요청을 만들고, 업체별 회신을 입력한다. 세 업체 회신이 모두 저장되면 의뢰인이 선택할 수 있는 상태로 자동 전환된다.
- 보고서는 초안 → 검토 요청 → 관리자 승인 → 최종 발행 순서만 허용한다. 수정·승인 취소·발행본 회수에는 사유와 감사기록이 남는다.
- 원본 파일은 비공개 버킷에 저장하고 조직·점검 UUID 경로와 SHA-256을 기록한다.
- JPG·PNG·TIFF는 실제 파일 머리값을 확인한 뒤 저장하며, 상대 분석 API는 로그인한 사용자만 호출할 수 있다.
- 최초 조직 개설에는 이메일 인증과 30일 안에 한 번만 쓸 수 있는 개설 코드가 필요하다. 이후 초대는 `invite-platform-user` Edge Function이 처리한다.

## 열화상 분석 데모

브라우저가 JPG·PNG를 작은 표준 픽셀 배열로 변환하고 `/api/thermal/analyze`가 색상 분포 기반 상대 후보를 계산한다. 외부 AI API를 사용하지 않는다. 분석이 실패해도 저장된 원본에서 분석만 다시 실행할 수 있으며, 한 원본에는 성공 결과를 한 건만 만든다. 실제 섭씨 온도는 방사온도 정보가 포함된 카메라 원본과 전용 파서를 연결해야 한다.

## PDF 요구사항 데모 범위

- 촬영 자료 업로드와 유효 조건·개인정보 마스킹 확인
- 이상 후보 유형 수정과 관리자 확정·기각
- 기대발전량, PR, 손실, 수익과 회수기간 계산
- 보고서 승인과 최소 11pt A4 인쇄·PDF 저장
- 업체 3곳 견적 비교와 설정 수수료 반영
- 설비·고객·업체 기준정보와 설정 판본 관리
- 고객 설비 등록, 고지서 샘플 진단, 보고서, 견적, 마이페이지, FAQ

`/demo`의 입력은 새로고침하면 초기화된다. 운영 화면의 발전소·점검·파일·후보·보고서·유지보수·업체 견적은 Supabase에 저장된다. 실제 OCR·Claude 호출, 방사온도 원본 파서, 외부 업체 자동 발송과 결제·정산은 후속 범위다. 운영 화면과 보고서는 휴대전화 너비부터 데스크톱까지 반응형으로 배치된다.
